# Program.cs — API composition root

- **Identity:** Top-level startup in `backend/OMStationary.Api/Program.cs`; API target is `net10.0` with EF Core SQL Server 10.0.0 and Swashbuckle 10.0.0.
- **Purpose:** Host composition, DI, authentication, CORS, throttling, best-effort DB initialization/development seeding, response headers, health route and controller mapping.
- **Data access:** Registers `OmDbContext` with SQL Server from `ConnectionStrings:DefaultConnection`.
- **DI registrations:** Singleton `TokenService` and `ICodPaymentProvider` (`CodPaymentProvider`); scoped `FirstPartyFulfillmentProvider`/`IFulfillmentProvider`, `FulfillmentSelectionService`, `CouponService`, `SettlementService`, `InvoiceService`, `NotificationService`, `StoreSettingsService`, `IWhatsAppNotificationService`, `StockAlertService`, `IEmailNotificationService`, and `IPaymentGateway` factory. The payment factory selects `PaytmQrPaymentGateway` only when provider is `Paytm` and `Payments:Enabled`; otherwise it supplies `UnconfiguredPaymentGateway`. Typed/named HTTP clients configure Paytm QR, WhatsApp and SMS services; their timeouts are 20 seconds. WhatsApp, email and SMS options bind from configuration sections. Controller discovery, endpoint explorer and Swagger generation are registered.
- **Authentication/configuration:** The `Bearer` scheme uses `JwtAuthenticationHandler`. Missing JWT signing key outside Development throws; Development generates an ephemeral key. Key must contain at least 32 UTF-8 bytes. Non-Development requires configured exact HTTPS, non-loopback CORS origins; Development defaults to localhost Vite origins. CORS policy allows configured origins, any header and method.
- **Rate limits:** `order-writes` is 60/minute and `tracking-reads` 120/minute with no queue; partition uses signed-in NameIdentifier, then remote IP, then `"unknown"`. Rejections return 429.
- **Startup database work:** Attempts `SafeMigrationBootstrap.ApplyAsync`. Development seeds five categories and twelve products only when respective tables are empty. Ensures Customer/Admin/PartnerShop/DeliveryPartner roles exist. Bootstrap admin creation requires configured email and password; password overwrite is opt-in and checks a hash before updating. Startup exceptions are logged and swallowed so host startup continues; this does not establish DB availability.
- **HTTP pipeline/endpoints:** Adds nosniff/referrer/frame headers and catches request exceptions to return a generic 503 unless the response already started. Swagger UI is Development-only. Order is CORS, rate limiter, authentication, authorization, `/api/health`, then controller routes. `/api/health` checks database connectivity and returns service status; source presence is not runtime evidence.
- **Local helpers:** `Slugify`, `PartitionKey`, and seed-product factory `Seed` each have a method report under `functions-methods/backend`. Inline lambdas/callbacks are not all independently documented.
- **Test evidence:** NOT TESTED; no application startup or health request was executed.
- **Maintenance:** Verify this registration/middleware order alongside endpoint attributes; secrets and external-provider configuration are read from configuration and are not documented here. No live DB/runtime status is asserted.
